# 企业数据仓库管理平台

面向企业数据团队的一站式数据仓库建设与管理平台。覆盖原始数据落地、多层清洗转换、维度建模、事实建模、分区治理、质量校验、血缘追踪与历史补数的完整数仓链路。

这是一个前后端分离的管理平台：前端 React + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 补数链路（历史重跑 -> 调度待办 -> ETL 任务）

补数不是两个独立页面各自记账，而是同一条链路：

```text
重跑批次(backfill) --登记/启动/暂停/恢复--> 调度待办(scheduling_todos) --读取--> ETL任务页
        |                                        |
        +---- 执行记录(backfill_runs, 只追加) ---+
```

- 登记：保存完整日期范围（`开始日期`~`结束日期`）、`覆盖模式`、`并行数量`；
  支持 `BEGIN-20260901` 这类前缀写法，校验失败时逐项说明原因。
- 状态：`草稿 -> 运行中 -> 已暂停 -> 已完成` 单向推进。重复提交启动幂等，
  运行中或已完成的批次不会被再次写入执行记录。
- 执行结果：`成功 / 部分成功 / 中断 / 超时 / 失败`。超时或中断后只把
  异常区间留待下次恢复，已成功区间不会重复写入；暂停后恢复沿用登记时的覆盖模式。
- 依赖：关联的 ETL 任务未完成、执行失败或重试耗尽时，批次不能进入运行中，
  待处理原因会写进调度待办，并同步展示在重跑页与任务页。
- 水位：执行记录只追加并带全局 `seq`，依赖结果冲突时以 `seq` 最大的已持久化
  记录为准；重跑页、任务页和异常区间显示同一个已完成水位与缺口。

相关接口：`GET /api/backfill/todos`、`GET /api/etl/todos`（同一份待办），
`GET /api/backfill/runs`、`GET /api/etl/executions`（只追加的执行记录）。

| 数据湖存储 | `lake` | 湖存储节点 | 节点编号、存储路径、文件格式 |
| 表结构演进 | `catalog` | 演进记录 | 记录编号、表名称、变更类型 |
| 运行监控面板 | `monitor` | 监控指标 | 指标编号、指标名称、监控对象 |
| 快照管理 | `snapshot` | 快照记录 | 快照编号、表名称、快照时间 |

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
